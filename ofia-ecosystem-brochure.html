OFIA — PRODUCT BLUEPRINT V1.0

One platform. Six applications. Seven vertical experiences.

A unified commerce and logistics ecosystem that gives every Nigerian business a storefront and operating experience built for its industry — and gives every customer one simple place to shop, book, and arrange delivery.

Product foundation

Every business gets an experience that already feels familiar.

Rather than forcing every business into one generic storefront, Ofia provides industry-specific experiences powered by shared commerce, customer, payment, and logistics capabilities. A car dealer feels like they're using a platform built for car dealers. A food vendor feels like theirs was built for food. Both run on the same underlying platform.

Industry-native

Each business gets a storefront and management interface suited to its industry — not a one-size-fits-all listing page.

Unified commerce

Products, services, bookings, orders, payments, and customer relationships work together on one store configuration.

Independent logistics

Customers and vendors can arrange dispatch and pickup on their own — with or without a store purchase involved.

The six applications

Shared foundations, vertical-specific surfaces.

Each application composes shared components (header, cart, checkout, booking engine, order management) with a vertical experience layer chosen by the store's configuration.

Storefront web

The vendor's own digital shop, not a marketplace listing — each vendor gets a unique storefront URL. Core screens: homepage, listings, product/service detail, booking, cart, checkout, order tracking, and store info.

Vendor dashboard (web)

The primary operating environment. Common navigation (overview, store, products, services, orders, customers, payments, logistics, analytics, settings) stays consistent while vertical-specific management screens change underneath it.

Logistics agent dashboard

Operational control centre for dispatch. Handles store-order deliveries, vendor dispatch, and independent customer or vendor pickup requests as one unified job queue, with live map, rider assignment, and exception handling.

Customer app

A native commerce app, not a web wrapper — vertical templates are coded into the app and populated from each vendor's store configuration. Logistics is a first-class feature, reachable without a purchase.

Vendor app

The mobile counterpart to the vendor dashboard, prioritising quick operational tasks: add a product, check orders, manage bookings, book dispatch — on the same store configuration as the web app.

Rider app

Job-oriented and deliberately narrow: accept, navigate, confirm pickup, transport, confirm delivery. Minimal steps, large touch targets, clear exception reporting.

Logistics job types

All delivery activity — however it originates — lands in the same operational job queue.

TYPE A

Store order delivery

A checkout with delivery selected generates the dispatch job automatically.

TYPE B

Vendor-initiated dispatch

A vendor creates a delivery request independent of any checkout.

TYPE C

Customer pickup request

A customer requests a rider to collect from one location and deliver to another.

TYPE D

Vendor pickup request

A vendor requests collection from a supplier, customer, or warehouse.

V1 release readiness

  • A vendor can register and create a store
  • A vendor can select one of the seven vertical templates
  • The storefront web app renders the selected vertical correctly
  • The customer mobile app renders the same store natively, with no web wrapper
  • The vendor can manage products and services from web and mobile
  • Store customization is reflected consistently across both customer interfaces
  • Customers can browse, purchase, and track orders
  • Customers can book enabled services
  • Customers can independently create pickup requests
  • Vendors can independently create dispatch and pickup requests
  • The logistics dashboard can receive and assign jobs
  • Riders can accept, execute, and complete jobs
  • Customers and vendors receive relevant status notifications
  • Payments and order statuses remain consistent across applications
  • The system supports multiple businesses operating independently

Final design principles

One coherent experienceA vendor should never feel like they're operating disconnected tools.
Shared foundationsIndustry-specific experiences shouldn't require duplicating the platform.
Native mobile renderingStorefronts render through coded templates, never embedded web pages.
Consistent vendor operationsWeb and mobile share store configuration, data, and workflows.
Commerce firstProducts are central; services and requests are flexible add-ons.
Logistics is independentDispatch works with or without a store purchase.
Simple by defaultShow the controls a business needs, not every feature on the platform.
Progressive capabilityVendors enable more as their business grows.
Brand flexibilityEvery storefront should feel like the vendor's own digital shop.
Built for extensionNew verticals arrive through templates and configuration, not rewrites.
